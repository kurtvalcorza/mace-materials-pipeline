#### Description

`mace-foundations/mace-mp-0` at revision `e291ace2bfae073c3ebc7ae2f9479a525989baa7` mirrors the MACE-MP-0 family of universal machine-learned interatomic potentials (Batatia, Benner, Chiang et al., 2023): equivariant message-passing models trained on the Materials Project trajectory dataset (MPtrj; PBE and PBE+U energies, forces and stresses) covering 89 elements. The file packaged here, `mace-mp-0b2-small.model` (67,622,684 bytes, SHA-256 `d5773bf9…`), is the "0b2 small" checkpoint published in the upstream GitHub release `mace_mp_0b2` on 2024-11-12 as `mace-small-density-agnesi-stress.model` — byte-identical to the Hub file — and is the model `mace.calculators.mace_mp(model="small-0b2")` downloads. Its extracted configuration: `ScaleShiftMACE`, 8,221,984 parameters in float64, two interactions (`RealAgnosticDensityInteractionBlock` then `RealAgnosticDensityResidualInteractionBlock`), hidden irreps `128x0e`, `max_ell` 3, correlation 3, 8 Bessel functions with a polynomial cutoff of order 5 at `r_max` 5.0 Å, the Agnesi distance transform, ZBL pair repulsion, a `16x0e` SiLU non-linear readout, 89 per-element reference energies, `avg_num_neighbors` 61.96 and an interaction energy scale of 1.7895 eV. A structure enters as atomic numbers, positions, a cell and periodic flags; the model returns a total energy, per-atom contributions, forces as the analytic negative gradient of the energy with respect to positions, and stress as the gradient with respect to a virtual strain.

What this repository adds is the `MaceMaterialsPipeline` class in `src/mace_materials_pipeline/pipeline.py`: manifest verification of the Hub snapshot before any model library is imported (`verify_snapshot`, which also checks the converted pair against the pinned digests when it is present), fresh-clone staging at the pinned revision (`stage_missing_files`), a **static audit of the pickled source** that disassembles the outer archive and every nested TorchScript archive with `pickletools`, collects every global, every fx-generated source string, every exec'd import block and every TorchScript source, and refuses anything outside the torch / e3nn / mace allow-lists or carrying forbidden tokens (`audit_model_file`, digest `9bb150f1…` pinned), a **one-time conversion** to a JSON config plus safetensors state dict of a freshly constructed model, checked tensor-by-tensor for bit-identity with the pickle (`convert_model`), model construction from the installed `mace-torch` with the config's architecture fields asserted against the package constants first (`build_model`), structure validation with named ceilings (`validate_inputs`), energy / per-atom energy / force / stress prediction (`predict`), per-atom energy and force errors against reference labels (`evaluate`), least-squares calibration of the per-element reference energies to a new level of theory (`calibrate_e0`), bounded fine-tuning of the readouts, reference energies and scale/shift block plus the last *n* interaction and product blocks (`adapt`), and a safetensors adapter artifact that is digest-verified before deserialization (`save_artifact`, `from_artifact`). Extended-XYZ I/O and an EMT-labelled sample generator live in `samples.py`; the metrics and the two trivial baselines in `metrics.py`.

Two things about this profile are stated rather than hidden. **The served model is a conversion, and the conversion is measured.** Beyond the ≤ 2.8×10⁻¹⁴ eV parity above, the rebuilt model passes the physics checks an interatomic potential must pass: rotating a structure leaves its energy unchanged to 0.0 and rotates its forces to 1.5×10⁻¹⁴ eV/Å, translation and atom permutation change nothing, the force on an atom equals the central finite difference of the energy to 2×10⁻⁹ eV/Å, and a 2×1×1 supercell has twice the energy to 1.8×10⁻¹⁵ eV/atom. The pickle's state dict and the current `mace-torch` layout differ in nine buffers — three stale ZBL cutoff buffers the current forward does not read are dropped, six boolean path-pruning flags the current constructor registers are added — and `convert_model` refuses any other drift. **The tutorial's reference labels are not DFT.** The sample dataset is labelled with ASE's effective-medium-theory potential, chosen because it is a real, deterministic potential for Cu and Al that runs inside the notebook; it is a different level of theory from the PBE data MACE-MP-0 learned, which is what makes the fine-tuning meaningful, and it is also a toy, which is why no number here says anything about DFT accuracy.

#### Intended Use and Limitations

###### Primary Intended Uses

Two tasks are exposed. **Energy, force and stress prediction:** input is 1 to `MAX_STRUCTURES_PER_CALL = 32` structures, each a `{symbols, positions, cell, pbc}` mapping in ångström with 1 to 512 atoms drawn from the 89 supported elements and at most 4,096 atoms per call; output per structure is the total energy (eV), the energy per atom, per-atom energy contributions, forces (eV/Å) and — for fully periodic cells — the stress tensor (eV/Å³), all from the pinned foundation potential. **Fine-tuning to local reference data:** given at least 8 structures labelled with energies and forces from one consistent reference (a DFT code and functional, or another potential), the pipeline calibrates the per-element reference energies and fine-tunes a bounded subset of the model, then predicts with the adapted potential and exports the changed tensors as a portable adapter. Envisioned application domains are materials workflows where a universal potential is a starting point rather than an answer — screening candidate structures before a DFT calculation, estimating forces and stresses for a composition the operator has some reference data for, adapting the foundation potential to a functional or a system the operator's own calculations cover, and teaching or evaluating foundation-model fine-tuning for atomistic simulation. In a larger system the pipeline is a single-point evaluator and an adaptation baseline whose output feeds a simulation engine or a scientist's judgement; it is not a molecular-dynamics driver, an optimiser or a workflow manager.

###### Primary Intended Users

Intended users are computational materials scientists, chemists and machine-learning engineers who work with atomic structures and reference calculations, in research, internal enterprise, or the DIMER model workbench. The pipeline assumes its users understand that a universal potential encodes the statistics of the Materials Project's PBE/PBE+U trajectories, not the physics of their system; that an energy from a machine-learned potential is only meaningful relative to other energies from the same potential and reference; that fine-tuning to a narrow dataset can erode the potential's behaviour outside that dataset (upstream mitigates this with multi-head replay against the original training data, which this repository does not implement); that frames from one trajectory or relaxation are near-duplicates and a random split across them leaks; that units are ASE's (eV, Å, eV/Å³) and that a stress sign convention must be checked against the consumer's; and that structural validation says nothing about whether a structure is chemically sensible.

###### Out-of-scope use cases

1. **Capability boundary:** the pipeline computes single-point energies, forces and stresses and fine-tunes to labelled structures. It does not run molecular dynamics, geometry or cell optimisation, phonons, transition-state searches or free-energy methods; it does not reproduce the published MACE-MP-0 benchmarks; it does not expose the medium or large 0b2 checkpoints, the MACE-OFF organic potentials, the MPA-0 or OMAT-0 models, multi-head replay fine-tuning, LAMMPS export or the CUDA-equivariance kernels; and it does not verify that a structure is charge-neutral, near equilibrium, or physically meaningful.
2. **Input boundary:** structures are `{symbols, positions, cell, pbc}` mappings with element symbols from the 89 MACE-MP-0 supports (Z 1–83 and 89–94; Po, At, Rn, Fr and Ra are refused), finite coordinates within ±10,000 Å, no two atoms closer than 0.5 Å including periodic images, a finite 3×3 cell whenever any periodic flag is set with vectors under 200 Å and periodic heights of at least 1 Å, at most 512 atoms per structure and 4,096 per call; labels are a finite energy of at most 1,000 eV/atom in magnitude and an (n_atoms, 3) force array within ±1,000 eV/Å. Charged systems, external fields, spin states, magnetic moments and isotopes are not inputs; molecules are accepted as non-periodic structures but the training data is bulk materials.
3. **Decision boundary:** not for autonomous action on a predicted stability, phase, mechanical property or reaction energy — materials selection, process control, safety cases, or any use where a wrong energy has consequences beyond a wasted calculation — without validation against the deployment's own reference calculations and expert review. A predicted energy is a screening estimate, not a determination.
4. **Provenance boundary:** not for settings that require the exact upstream serialized object to be executed, or that forbid any one-time unpickling of a third-party checkpoint even after a static audit; the conversion's trust boundary is documented under *Mitigations* and in `docs/WEIGHTS.md`, and a deployment that cannot accept it must not use this pipeline.

#### Factors

###### Groups

The pipeline's inputs are atomic structures, not records about people, so age, gender, skin type and socioeconomic status are not attributes of any input and no demographic evaluation applies. The relevant groups are chemical: the pretraining corpus is the Materials Project's PBE/PBE+U relaxation trajectories, so the potential is best on the inorganic crystalline chemistries the Materials Project covers and progressively less reliable on molecules, surfaces, amorphous phases, strongly correlated or magnetic systems, high-pressure phases, and elements that are rare in the corpus; the upstream authors publish per-task benchmarks, not a per-element or per-chemistry error breakdown for this checkpoint, and this repository measures none. The tutorial exercises two elements (Cu, Al) in one lattice; the other 87 elements and every other structure type are unmeasured here.

###### Instrumentation

There is no physical sensor in this pipeline. The instruments that matter are the codes that produced the reference labels — the DFT code, functional, pseudopotentials, k-point density, smearing and convergence settings, or the classical potential — because a fine-tuned model inherits every systematic choice in them and cannot tell two references apart; and, for prediction, the structure source (an experimental refinement, a relaxed DFT cell, a generated candidate), whose errors pass straight through. The model's own instrument is its neighbour list: interactions are truncated at `r_max` 5.0 Å per layer, so effects that act beyond about 10 Å (two message-passing steps) are invisible to it by construction. The tutorial's instrument is ASE's EMT calculator: deterministic, analytic, parameterised for seven fcc metals, and not a substitute for any electronic-structure method.

###### Environment

Operating environment: Python 3.12 with `torch==2.14.0`, `torchvision==0.29.0`, `mace-torch==0.3.16`, `e3nn==0.4.4`, `ase==3.29.0`, `numpy==2.5.3`, `safetensors==0.8.0`, `huggingface-hub==1.32.0` (`pyproject.toml`); `mace-torch` brings `opt_einsum`, `matscipy`, `torch-ema`, `torchmetrics`, `h5py`, `lmdb`, `orjson`, `pandas`, `matplotlib`, `GitPython` and others as its own dependencies. The model runs in **float64**, as upstream ships it and as `build_model` sets the default dtype; `device` defaults to `cpu` and the notebook selects CUDA when visible. Two runtime facts to know: importing `mace` sets `TORCH_FORCE_NO_WEIGHTS_ONLY_LOAD=1` process-wide (so that e3nn 0.4.4 can load its Wigner constants under torch ≥ 2.6), which affects any other `torch.load` in the same process — this pipeline loads its own artifacts through safetensors only — and `mace-torch` is not the version the checkpoint was pickled with, which is why the conversion normalises the nine-buffer layout difference recorded under *Description*. Verified locally in a dedicated Windows venv on `torch 2.14.0+cpu`; the recorded run is under "Runtime" (audit + conversion 5.7 s, load 1.0 s, 8 structures of 32 atoms predicted in 0.67 s, an 8-epoch adaptation on 27 structures in 52 s). Data environment: the model assumes structures resembling Materials Project chemistry given in ångström with a sensible cell; it degrades, without any error, on chemistries and geometries far from that corpus.

#### Metrics

###### Performance Measures

The pipeline reports, exactly as `metrics.regression_metrics` names them: `energy_mae_per_atom` and `energy_rmse_per_atom` (eV/atom, total energy error divided by the atom count, because total energies scale with system size), `force_mae` and `force_rmse` (eV/Å over every Cartesian force component), with `n_structures` and `n_atoms`. Force errors are the headline for a potential that will drive geometry or dynamics; per-atom energy errors are the headline for stability and phase questions. Three comparison points are reported with the same fields. `composition_baseline` fits one energy per element on the training split (E = Σ n_element × E0_element) and predicts zero forces — **blind to geometry by construction**, so its energy error is the within-composition spread of the labels and the number any adapted model must beat. `zero_force_baseline` is the mean absolute reference force, the magnitude a force model must beat. The **frozen foundation model** is evaluated as is, and again after E0 calibration as epoch 0 of every adaptation, so the adapted number is read against what the pretrained potential already knew. Every metric in this repository is sample-sanity evidence on generated structures from one seeded split with no dispersion estimate; no number from the MACE-MP-0 paper is reproduced or claimed.

###### Decision thresholds

There is no classification and no decision rule in the pipeline: `predict` returns continuous energies, forces and stresses and applies no threshold to any of them. The limits that *were* fixed during development are input-contract limits, not decision thresholds — `MAX_STRUCTURES_PER_CALL = 32`, `MAX_ATOMS_PER_STRUCTURE = 512`, `MAX_ATOMS_PER_CALL = 4096`, `MIN_INTERATOMIC_DISTANCE = 0.5` Å (closer than any chemistry, where the ZBL core dominates), `MAX_CELL_LENGTH = 200` Å, `MIN_CELL_HEIGHT = 1.0` Å, and the label magnitude ceilings — chosen so that a rejection names a real defect and an acceptance never means "physically sensible". An operator who needs a threshold (an energy-above-hull cut for screening, a force tolerance for convergence, a maximum-force gate for stability) must set it from validation against their own reference and own it; the pipeline supplies the numbers, not the rule. `adapt` selects the epoch with the lowest validation loss, which is the only selection this repository performs.

###### Approaches to uncertainty and variability

Reported metrics come from a **single seeded split**: `split_dataset` stratifies by composition with an explicit seed (default 0; the notebook uses 42) into train/validation/test, and `evaluate` scores one split once. No cross-validation, bootstrap, ensemble or repeated-run averaging is performed, and no dispersion is reported — with 12 test structures any interval would be dominated by the split. A caller who needs one repeats the workflow over seeds, or supplies enough labelled data for trajectory-aware folds, and owns that design. Sources of run-to-run variability: the sample generator and the split are seeded through `random.Random`; the fine-tuning's batch shuffling through a seeded `torch.Generator` and `torch.manual_seed`; EMT labels are deterministic; the tie-free forward is deterministic on CPU in float64 (the same batch predicted twice is bit-identical, and single-versus-batched prediction agrees to 1.4×10⁻¹⁴ eV); non-deterministic GPU kernel selection is not controlled. The pipeline produces no predictive uncertainty — no committee, no Bayesian head, no applicability-domain score — so a prediction far from the training distribution is returned with the same confidence as one inside it.

###### Mitigations

1. **Supply-chain integrity:** `MODEL_ID` and the 40-hex `MODEL_REVISION` are module constants; `verify_snapshot()` checks `modelId`, `revision`, and the byte size and SHA-256 of both manifest entries before any load, additionally asserts the source file's digest against the package constant `SOURCE_MODEL_SHA256`, and raises on the first mismatch (tests flip a digit, change the identity and delete a file and assert each raises). `stage_missing_files()` fetches only manifest-listed files absent on disk, only at `MODEL_REVISION`, only when `allow_download=True`, and refuses a manifest naming another model. `.gitattributes` carries `weights/** -text`.
2. **Executable serialization handled explicitly (asset spec §11.2):** the pickle is never loaded by the runtime path. `audit_model_file` disassembles it with `pickletools` (outer archive, 18 nested TorchScript archives), collects 61 globals, 28 fx-generated sources, 10 exec'd import blocks and 30 TorchScript sources, and refuses any global outside `torch` / `e3nn` / `mace` / `collections` / `_codecs` / `__torch__` (plus `__builtin__.set`), any import line outside seven allow-listed lines, any forbidden token (`os`, `subprocess`, `exec`, `eval`, `socket`, `sys`, `importlib`, `pickle`, `urllib`, …) in any generated source, and any bare-name call in generated code; the audit digest is pinned. `convert_model` runs the size check, the digest check and the audit before the single `torch.load(weights_only=False)`, refuses an unexpected model class, asserts the extracted config against the package constants, loads the pickled tensors into a freshly constructed model with exactly the nine-buffer layout difference documented and nothing else, verifies every carried tensor is bit-identical, and writes safetensors. Tests craft pickles with `os.system`, `builtins.eval`, a `subprocess` call in generated code, an `import os` in an import block and an `os.getcwd()` in a nested TorchScript source, and assert each is refused before anything is unpickled.
3. **Deterministic, digest-pinned serving pair:** the conversion is reproducible (same digests on repeated runs and inside the executed notebook), `verify_converted` checks the pair's sizes and SHA-256 against `CONVERTED_SHA256` / `CONVERTED_BYTES`, `_config_from_json` asserts the architecture fields against the package constants before any model library is imported, and the model loads with `strict=True` and a parameter-count check. With `require_source=False` (the DIMER-hosted case) the pair alone is accepted, still digest-verified.
4. **Conversion fidelity evidence, stated with its limits:** energy parity ≤ 2.8×10⁻¹⁴ eV and force parity ≤ 3.6×10⁻¹⁵ eV/Å against the pickled model and the upstream `MACECalculator` on three structures; the physics checks under *Description*. The comparison was made under the same `mace-torch` version on both sides; behaviour of the pickle under the version it was trained with was not measured.
5. **Artifact integrity and scope:** the adapter is safetensors, not a pickle. `load_artifact` validates the manifest **before** deserialising anything: the artifact format and `format_version`, the recorded base model id, revision and converted-base digests, exactly one weights entry named `adapter.safetensors` that resolves inside the artifact directory, an in-range `adapter.trainable_blocks`, and a tensor list equal to the exact set that scope may change on this base (`readouts.*`, `atomic_energies_fn.*`, `scale_shift.*` plus the trailing interaction/product blocks); the safetensors keys must then equal that set and every shape must match. The weights file's SHA-256 is checked against the adjacent manifest — it detects corruption or drift of the file relative to that manifest, not authenticity: an actor who can replace both files can make them agree.
6. **Input integrity:** `predict`, `evaluate`, `calibrate_e0`, `adapt` and `validate_inputs` route through one checker, so their acceptance criteria cannot diverge; it rejects unsupported and malformed element symbols, non-finite or out-of-range coordinates, shape mismatches, periodic flags without a cell, singular or oversized cells and sub-ångström periodic heights, atoms closer than 0.5 Å including periodic images, malformed labels, too many atoms and too many structures. `validate_dataset` additionally rejects missing labels, duplicate names and too few records.
7. **Import boundary:** verification, the static audit and validation run before `torch`, `e3nn`, `mace`, `safetensors` or `huggingface_hub` are imported (DIMER RTM-001); `tests/test_import_boundary.py` fails if a rejected request reaches a model library, and an AST check fails if any of them is imported at module level.
8. **Statistical mitigations:** `split_dataset` stratifies by composition; every structure of a composition has the same atoms, so the composition baseline is blind to geometry by construction; the frozen model's error is reported beside the adapted number; validation is used for epoch selection only and the test split for nothing but the final evaluation.
9. **Honest scope:** validation is labelled structural, EMT is labelled a toy reference, the physics checks are labelled necessary rather than sufficient, and no upstream benchmark is claimed.

Not implemented, and therefore not claimed: no multi-head replay or any protection against forgetting during fine-tuning, no uncertainty estimate, no applicability-domain check, no trajectory-aware splitting, no chemical-sanity checks, and no measurement on any element or structure type beyond the two-element fcc sample.

###### Risks and harms

1. **A conversion can be subtly wrong:** the evidence is bit-identical tensors, parity on three structures and the physics checks — all under one `mace-torch` version. A future `mace-torch` that changed a block's semantics while keeping its parameter names would load strictly and silently compute something else; the exact pin is the control, and the parity test is the check to re-run before changing it.
2. **A pickle audit is an allow-list, not a proof:** the static audit bounds what the unpickler can import and what generated code can name; it cannot prove the absence of a construction the allow-listed classes themselves could be abused for. The digest pin means the audited bytes are the loaded bytes, and the conversion happens once, in the operator's environment.
3. **Catastrophic forgetting:** fine-tuning 1.92 M parameters to 27 structures of two elements improves those structures and says nothing about the other 87 elements or other geometries; the adapted potential may be worse than the foundation model everywhere the training set is not. Nothing in the output flags this.
4. **Trajectory leakage inflating every metric:** frames from one relaxation or MD run are near-duplicates; a random split across them makes memorisation look like generalisation. Likelihood is high for any real dataset, and neither the model nor this repository can detect it.
5. **Confident nonsense outside the domain:** a molecule in vacuum, a surface, a highly charged defect or an exotic phase is scored with the same silent confidence as a bulk oxide; there is no uncertainty and no domain flag.
6. **Units and conventions:** eV, Å and eV/Å³ with ASE's stress sign; a consumer expecting kJ/mol, GPa or the opposite stress sign gets wrong numbers without an error.
7. **Reference inconsistency read as model error:** labels mixed from two DFT settings are unlearnable, and the symptom looks like a bad model rather than bad data.
8. **Proprietary data in a hosted runtime:** the realistic confidentiality failure is an unpublished alloy dataset uploaded to a cloud notebook. Inference is local, but the runtime may not be the operator's.

###### Use cases

The model must not be used to present predicted energies, forces, stresses or derived properties as validated results in a safety case, a regulatory submission, a process-control decision or a materials-qualification decision without validation against the deployment's own reference calculations and expert review; it must not be used to drive simulations whose outcome has consequences for people or equipment on the strength of the checks in this repository; it must not be used as an oracle for chemistries outside the Materials Project's coverage without measuring its error there first; it must not be used to load or execute the upstream pickle in any way other than the audited, digest-verified, one-time conversion this repository performs; and it must not be used in any way that breaches the MIT terms of the upstream weights or the DIMER deployment terms.

## Input/output contract

- `MaceMaterialsPipeline.from_pretrained(device="cpu", weights_dir=None, allow_download=False, require_source=True, report=None)`: stages and verifies the snapshot, audits and converts the source when the pair is absent (reporting through `report`), asserts the converted config against the package constants, builds `ScaleShiftMACE` from the installed `mace-torch` and loads the safetensors strictly. `require_source=False` accepts a digest-verified converted pair without the pickle or the manifest.
- `predict(structures, *, batch_size=8) -> dict` with `model` (id, revision, key, `adapted`), `units`, `results` (per structure: `name`, `n_atoms`, `periodic`, `energy`, `energy_per_atom`, `node_energies`, `forces`, `stress` or `None`), `seconds`.
- `evaluate(structures, *, batch_size=8) -> dict`: `n_structures`, `n_atoms`, `energy_mae_per_atom`, `energy_rmse_per_atom`, `force_mae`, `force_rmse`, `units`.
- `calibrate_e0(structures) -> dict`: least-squares per-element offsets added to the model's reference energies; returns `elements`, `shifts_ev`, `n_structures`.
- `adapt(train, val=None, *, epochs=6, lr=1e-3, batch_size=4, trainable_blocks=1, energy_weight=100.0, forces_weight=10.0, calibrate=True, seed=0, progress=None) -> dict`: bounded Adam fine-tuning; returns the trainable prefixes and counts, hyperparameters, calibration, split sizes, `best_epoch`, per-epoch `history` (epoch 0 = the calibrated frozen model, each with `train_loss`, `val_loss` and validation metrics) and `seconds`.
- `save_artifact(output_dir, metadata=None) -> Path` writes `adapter.safetensors` (the tensors under the trainable prefixes) + `manifest.json` (format, base model id/revision/key and converted digests, adaptation record, history, tensor names, file size and SHA-256); `from_artifact(...)` / `load_artifact(...)` verify all of that before deserialising.
- `validate_inputs(structures) -> dict` (`n_structures`, `n_atoms`, `elements`, `periodic`, `min_distance`, `labelled`) and `validate_dataset(records, *, min_records=8, require_labels=True) -> dict` (normalised `records`, counts, `compositions`, `elements`, `labelled`, `digest`) raise exactly what the execution path would raise. `split_dataset(records, *, val_fraction=0.2, test_fraction=0.25, seed=0)`, `load_byod_dataset(path)` (extended XYZ) and `write_dataset_xyz(records, path)` are the dataset primitives; `to_atoms` / `from_atoms` bridge to `ase.Atoms`; `structure_digest` and `dataset_digest` pin geometry and labels.
- `audit_model_file(path=None) -> dict`, `convert_model(path=None, *, audit=True) -> dict`, `verify_converted(path=None) -> dict` and `build_model(config)` are the serialization primitives.
- Constants: `R_MAX = 5.0`, `NUM_INTERACTIONS = 2`, `HIDDEN_IRREPS = "128x0e"`, `NUM_ELEMENTS = 89`, `SUPPORTED_ATOMIC_NUMBERS` (Z 1–83, 89–94), `PARAMETER_COUNT = 8221984`, `STATE_TENSORS = 86`, `MAX_STRUCTURES_PER_CALL = 32`, `MAX_ATOMS_PER_STRUCTURE = 512`, `MAX_ATOMS_PER_CALL = 4096`, `MIN_INTERATOMIC_DISTANCE = 0.5`, `MAX_CELL_LENGTH = 200.0`, `MIN_CELL_HEIGHT = 1.0`, `ENERGY_WEIGHT = 100.0`, `FORCES_WEIGHT = 10.0`, `ARTIFACT_FORMAT = "org.valcorza.mace-materials.adapter.v1"`.

## DIMER deployment notes

| Field | Status |
|---|---|
| **DIMER status** | **Planned / conditional** — the asset-format and deserialization-trust review DIMER requires is what this repository implements; the review's acceptance is the maintainer's call |
| Licence | MIT (weights, the upstream `mace` code and this repository's dependencies) — use, modification, redistribution and commercial use permitted with the licence and notices preserved |
| Weights | Would be redistributed converted, not unmodified: the served artifact is the deterministic safetensors + JSON pair derived from the pinned pickle, with both identities recorded (asset spec §11.2); this repository redistributes neither |
| Remote code | **Not required** — no Hub-hosted module is imported and `trust_remote_code` does not exist in this stack; the model class comes from `mace-torch==0.3.16` on PyPI |
| Executable serialization | The `.model` pickle is unpickled **once**, at conversion, after a digest check and a static audit; a DIMER profile should carry the converted pair and never the pickle |
| Runtime | `mace-torch==0.3.16` + `e3nn==0.4.4` + `torch==2.14.0` + `ase==3.29.0`; float64; importing `mace` sets `TORCH_FORCE_NO_WEIGHTS_ONLY_LOAD=1` process-wide |
| Upload format | `mace-mp-0b2-small.safetensors` (67,400,566 bytes, SHA-256 `2ed99065…`) + `mace-mp-0b2-small.config.json` (3,279 bytes, SHA-256 `130b6411…`); **the `.model` file must not be uploaded** |
| Input contract | Structures as `{symbols, positions, cell, pbc}` mappings or extended XYZ; energies in eV, forces in eV/Å, stress in eV/Å³ |

**The open question is the trust boundary, not the licence or the code.** DIMER requires for this profile an asset-format/deserialization review, and assumes no silent conversion. This repository performs the conversion loudly: the source is immutable and digested, the audit is static and pinned, the conversion is deterministic and its fidelity is measured, and both asset identities are recorded — the shape the asset specification prescribes for a code-capable upstream format. What remains is whether a one-time, audited unpickle in the build environment (and in the tutorial runtime, where the notebook converts the downloaded file) meets the DIMER bar, or whether DIMER should host only the converted pair produced and verified once by the maintainer. Either way the served artifact is the same safetensors file.
