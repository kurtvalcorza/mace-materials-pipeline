## Two things this tutorial does that the fleet's others do not

**It converts the model it downloads.** The upstream asset is a pickled torch module. The model cell downloads and digest-verifies it, then `from_pretrained(..., report=print)` prints the static audit (every global, generated source and TorchScript source the pickle would execute, checked against allow-lists and a pinned audit digest) and the conversion record (a JSON config and a safetensors file with pinned digests, 3 stale buffers dropped and 6 flag buffers added) before the model is rebuilt from the installed `mace-torch` and loaded strictly. The generator's Section 3 prose describes Hub staging; the intro, the Prerequisites and the printed report say what happens to the pickle.

**It checks physics before accuracy.** Section 5 rotates, translates and permutes a structure, compares the analytic force with a central finite difference of the energy, and doubles a cell — assertions a wrongly rebuilt potential would fail before any error metric is read.

## Conformance notes

- **Standalone carrier (ST1–ST8):** the primary path performs no clone, repository install, or repository import. Section 2 embeds the repository's 3 modules (`pipeline.py`, `samples.py`, `metrics.py`) verbatim in topological dependency order (each tagged `metadata.dimer.embedded_module`; the only rewrites make `DEFAULT_WEIGHTS_DIR` working-directory-relative and remove internal relative package imports), Section 3 carries the 2-file snapshot manifest inline and asserts it against the module's constants before fetching, and `NOTEBOOK_SOURCE` records the repository, revision and module digests in the exports.
- **Parity (PAR1–PAR4):** `tests/test_notebook_parity.py` and `tools/validate_release_assets.py` fail when the carried modules, the inline manifest, or the inline pins differ from the repository, or when the notebook is not byte-identical to the generator's output.
- **Model acquisition (MOD1–MOD9):** `stage_missing_files(WEIGHTS_DIR, allow_download=True)` fetches only the manifest entries that are absent, from the Hugging Face Hub at the immutable revision (never `main`); `verify_snapshot` re-hashes both entries and asserts the source digest against the package constant; `MaceMaterialsPipeline.from_pretrained(weights_dir=...)` audits and converts the source when the pair is absent, verifies the pair against pinned digests, asserts the config against the package constants, builds the model from `mace-torch` and loads strictly. The pickle is unpickled exactly once, in that conversion, after the audit.
- **Stages (§4.1):** `generate_sample_dataset` / `load_byod_dataset` (sample acquisition) → `validate_dataset` (validation, with the ceilings and a dataset digest) → `split_dataset` (composition-stratified train/validation/test) → `validate_inputs` refusal probes → `pipe.predict` with physics assertions → `composition_baseline` + `zero_force_baseline` + `pipe.evaluate` on the frozen model (baselines) → `pipe.adapt` (E0 calibration + bounded fine-tuning) → `pipe.evaluate` on validation and test with the comparison table (evaluation) → `pipe.predict` on new structures (inference) → `pipe.save_artifact` → `MaceMaterialsPipeline.from_artifact` with the parity assertion (export and reload).
- **Score semantics (UNC1–UNC4):** the outputs are continuous energies, forces and stresses with no threshold and no predictive uncertainty; the notebook states that units are ASE's, that nothing flags a structure outside the model's domain, and that the adapted potential may be worse than the foundation model away from the training set.
- **Baselines and evidence (EVAL6/EVAL10/EVAL11):** the composition baseline, the zero-force baseline and the frozen model are scored on the same test split as the adapted model, and every metric is labelled as tutorial sample-sanity evidence from one seeded split with no dispersion estimate. The sample gives every structure of a composition the same atoms, which is what makes the composition baseline blind to geometry, and labels with a potential that is not MACE's reference, which is what makes the calibration and adaptation meaningful.
- **Split integrity (SPL1–SPL8):** the split is explicit, stratified by composition and seeded; validation metrics select the epoch and the test split is used for nothing but the final evaluation. The notebook states that frames of one trajectory are near-duplicates and that real data must be split by trajectory or composition.
- **Ceilings (VAL6):** the element set, `MAX_STRUCTURES_PER_CALL = 32`, `MAX_ATOMS_PER_STRUCTURE = 512`, `MAX_ATOMS_PER_CALL = 4096`, `MIN_INTERATOMIC_DISTANCE = 0.5` Å, the cell limits and the label ceilings are stated in the Prerequisites and printed from the schema before the model runs; four refusals are demonstrated.
- **BYOD (DAT10–DAT19):** `USE_BYOD` defaults to `False` so the sample path never opens an upload dialog; when enabled, user data flows through the same validation, split, baselines, adaptation, evaluation, inference, export and reload cells. The expected extended-XYZ schema, the element support and the privacy guidance — proprietary compositions and unpublished reference datasets are restricted data — are stated in the Prerequisites and in Section 4, and the sample dataset is written to `outputs/mace_materials_sample_dataset.xyz` in that shape.
- `tools/validate_release_assets.py` performs source validation only. It does not satisfy the clean-runtime execution requirement; a release review must confirm that a recorded clean run in `../docs/release-verification.md` matches the notebook revision under review before the status is promoted to `Release-grade`.
